# NSE Insights UI/UX Fixes Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship all 7 fixes from the 30 Sep 2026 UI/UX review: language switch, plain step names, persistent stepper with Done cards, model tiers, download progress, one-button summaries, and one visual style. They sit on top of a "fix 0" that repairs the data bugs underneath them.

**Architecture:** The backend becomes the single source of truth for pipeline state: `GET /api/pipeline/status` is built from artefacts on disk, `data/pipeline_state.json` and an in-process jobs registry. Stream events gain machine-readable `stage`/`code`/`params` fields, so the React frontend translates them (custom `I18nProvider`, NL default) instead of showing backend English. Shared UI pieces (`Stepper`, `ProgressPanel`, `DoneCard`, `TierPicker`) replace the per-step one-offs.

**Tech Stack:** Flask + unittest (backend). React 19 + Vite 8 + Tailwind 3 + framer-motion (frontend). New dev deps: `vitest`, `@testing-library/react`, `@testing-library/user-event`, `jsdom`. New runtime deps: `material-symbols`, `@fontsource/manrope`, `@fontsource/inter`. Python: `huggingface_hub` (already installed transitively; pin it in `requirements-common.txt`).

**Spec:** `docs/superpowers/specs/2026-10-31-ui-fixes-design.md` (decisions D0–D13, the status contract, copy keys) and `docs/superpowers/specs/2026-10-31-ui-strings-inventory.md` (every string to replace). Source review: `docs/ui-review/index.html`. Mockups: https://claude.ai/artifact/9oSEtxo4yfrafwHqEJx56u, with local copies in `docs/superpowers/mockups/` (`Main.html` = step 1 done + needs_review + welcome banner, `Step2Running.html`, `Step3.html`, `Step4.html`, `Overview.html` = empty/not-ready/offline, `Mobile.html` = 390 px EN). UI tasks match these boards: layout, copy, colours and spacing. Inline styles in the boards are reference only; implement with Tailwind tokens.

**E2E:** Playwright (`@playwright/test`, Chromium) runs against the Vite dev server with the backend mocked via `page.route` fixtures (Task 4b). Every UI task from Task 7a on adds or extends a spec under `dashboard/e2e/` that drives its feature in a real browser and asserts the mockup state it implements.

## Global Constraints

- The default language is `nl`, saved in `localStorage['nse.lang']`. Every storage access goes inside try/catch.
- No user-visible English or Dutch literal in JSX under `dashboard/src/components`, `dashboard/src/pages`: all copy goes through `t()`. Exceptions: data values (column names, programme/location values) and technical model IDs, which appear only under Advanced.
- No emoji anywhere in the UI. Icons are Material Symbols Outlined only, through `<Icon name>`.
- The only accent colour is `primary #002f59`. Status colours (`success`, `warning`, `error`) are for status only.
- Theme names stay English as data and cache keys. They are displayed via `t('theme.<key>')`.
- Raw backend `message` text is shown only inside a "Details tonen / Show details" disclosure.
- Never delete the insight cache before a step has succeeded.
- Balanced tier = current defaults: `Octen/Octen-Embedding-0.6B` + `unsloth/gemma-4-12B-it-qat-GGUF:UD-Q4_K_XL`.
- Anonymisation: possible misses are never hidden. "Continue" stays disabled while `needs_review`. A skipped verification shows `unverified`, never green.
- `app.py` must not import `threading` (enforced by `tests/test_app_startup.py`). Thread-safe code lives in `src/pipeline/jobs.py`.
- All API calls go through `dashboard/src/services/api.js` (`API_BASE`). No new hardcoded `localhost:5001`.
- E2E tests never need the real backend or models: every `/api/` call is mocked through `e2e/fixtures/api.js`.

## Review Focus

These are the failure modes most likely to hit a real user that no feature test exercises. Each one has its test in the task named.

1. **The backend is not running.** The Overview and pipeline must show `overview.offline`, never zeros or "error" as a theme. *Test in Task 2.*
2. **The backend restarted mid-job.** The in-memory `active_job` is gone, and the step must read `interrupted`, never `in_progress` forever. *Test in Task 8.*
3. **Step 1 is re-run after steps 2–4 were done.** Downstream steps must show `stale`, not keep their green checks. *Test in Task 8.*
4. **llama-server is down or the model is missing when writing summaries.** The user needs a clear error within seconds, not 2.5 minutes of silent retries. *Test in Task 14.*
5. **Browser storage is blocked (private window).** The language falls back to `nl` with no crash, and the welcome banner still renders. *Test in Task 5.*
